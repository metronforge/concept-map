# Task: 0.2.0 — usable outside the book

Read first: [ARCHITECTURE](../ARCHITECTURE.md), ADRs
[0006](../adr/0006-no-book-vocabulary.md),
[0010](../adr/0010-universal-integration.md),
[0011](../adr/0011-source-map-and-layout.md),
[0012](../adr/0012-automated-releases.md). They are binding; where the code
disagrees, report it and stop that item.

The test of done: a person who has never seen the book writes a map of a
coffee shop (guest → cashier → barista; scenarios "normal" and "out of
milk") in about thirty lines, without coordinates, and shows it on a plain
HTML page with one `<script>` and one `<concept-map>`.

## Working rules

As in stage A: one pull request per item, an ADR for every new decision, no
speculative code, glossary names, guards stay green. Pull request titles in
Conventional Commits from item 1 on.

## Items, in order

1. **Release automation** (ADR 0012). Title check; release-please in
   `release.yml` with publish in the same run; config with
   `bump-minor-pre-major`; RELEASING.md rewritten. Dry run on a fork or a
   branch, evidence in the pull request.
2. **Format 3** (ADR 0006, 0011). Source and resolved schemas, layers in the
   map, `id` instead of `spread`, defaults for optional fields, plain-text
   leaves with inline markup. JSON Schemas for both levels. Update fixtures:
   the 23 book maps converted to format 3 with their hand geometry; render
   goldens must not change except where a difference is listed and explained.
3. **Layout port** (ADR 0011). `layout()`, `LayoutGraph`, `LayoutResult`,
   label measurement, the dagre and ELK adapters, I10 as a property.
4. **Engine comparison — stop for the author.** Both engines on the 23 book
   maps (sources with geometry stripped) and the coffee-shop map. One page
   with the hand layout, dagre and ELK side by side per map; a table of
   crossings, bends, area, time, bundle size, and whether the
   engine supports nested (compound) nodes, for ADR 0020. No default engine is chosen in
   code before the author's decision.
5. **Integration** (ADR 0010). `renderFigure`, `mount`, `<concept-map>`,
   entry points split; one browser test runs the same map through all three.
6. **Examples and README.** Three examples in three domains, each a plain
   HTML page with the package from a CDN and a source map without
   coordinates:
   - `examples/coffee/` — a process: guest → cashier → barista; scenarios
     "normal" and "out of milk".
   - `examples/door/` — a flat state machine: closed / open / locked;
     transitions labelled `event [guard] / action`, one self-transition;
     scenario "try to open a locked door". Pseudostates (initial, final)
     are drawn as small ordinary nodes until node shapes exist (0.3.0).
   - `examples/gcd/` — an algorithm: Euclid's GCD as a flowchart
     (input → `b = 0?` → `r = a mod b` → `a ← b, b ← r` → back; "yes" →
     return `a`). Scenarios "gcd(48, 18)" (three turns of the loop, the
     repeat badge on the loop edge, log lines `48 mod 18 = 12` …) and
     "gcd(5, 0)". The flow is written by hand; variable values go into the
     step text and the log until the state panel exists (0.3.0).

   README starts with the coffee example: map, one script tag, one element;
   then the three ways in; then links to the other two examples; nothing
   about the book above the fold. All examples are in English. Each example records what it had to work
   around; those notes are input for 0.3.0.

7. **Bring the code back in line with the architecture**, after item 6 and
   before the release. No change of behaviour; all browser tests and
   snapshots unchanged.
   - Telling a resolved map from a source map is a function of the schema
     module, not a `"viewBox" in input` check in the element.
   - Choosing the element's input by priority (property, `src`, inline JSON,
     server data) and deciding whether to reuse a server-rendered figure are
     pure functions in the core with unit tests; the shell only reads the DOM
     and calls them.
   - The lint rule that forbids classes in the core also covers
     `src/layout`.
   - A dependency rule forbids `dom` from importing `element`.
   - The architecture document: the core includes `layout`; the module table
     puts `mount` in `dom`; the glossary gains figure, mount, hydrate,
     element, layout engine and layout level.
