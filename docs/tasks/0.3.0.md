# Task: 0.3.0 — layouts that read like hand-drawn ones

Read first: [ARCHITECTURE](../ARCHITECTURE.md),
[ADR 0025](../adr/0025-layout-pipeline.md) (binding),
[ADR 0021](../adr/0021-layout-levels.md), and AGENTS.md, in particular
"Visual acceptance". Where the code disagrees with them, report it and stop
that item.

The test of done: the three examples and the 23 book maps, laid out
automatically with hints taken from their scenarios, have no hard defect in
the quality report in Chromium, Firefox and WebKit, and the author prefers
them to today's drawings on the comparison page.

## Working rules

One pull request per item, on `main`, in order. Stop after each item for
review. Items 1–4 change no drawing, except where the report proves that a
defect is removed; say which in the description. No new runtime dependency
without a decision record. Graphviz is not a dependency.

## Items

1. **Quality report.** A pure core function over a resolved map: edge
   crossings; labels crossed by a line, a box or a step number; step numbers
   over labels or boxes; loops touching other boxes; share of main-path edges
   that follow the reading direction; text scale. `layout()` returns it;
   `strict` turns hard defects into errors. The browser checks of "Visual
   acceptance" and the comparison page call the same function. Record the
   baseline of the hand-drawn maps.
2. **One problem description.** `LayoutProblem` with typed constraints and
   adapter capabilities; the `Placer` port; dagre and ELK behind it. A
   required constraint an adapter cannot honour is an error naming it.
   Drawings unchanged.
3. **Measure with the real font.** The `Measurer` port with the font-table and
   DOM adapters; the resolved map records which was used; `refine` in the
   browser re-places labels and numbers after fonts load and never moves a
   box.
4. **One stage for labels, step numbers, loops and line shape**, used by every
   engine and by hand layouts; candidates with costs, cheapest wins. Remove
   the per-adapter fixes it replaces.
5. **Intent from scenarios — stop for the author.** Derive order, main path
   and free (return) edges from the first scenario; pass them to dagre and
   ELK. The comparison page shows hand, dagre, ELK, each with and without
   hints, with the report beside every drawing. The author then reconsiders
   the default engine.
6. **Hints in the source format**: same row or column, free edge, side of a
   box; each with capability checks and an example.
7. **Relations.** Two pull requests.
   - Placement by our own solver in the core, no dependency: difference
     constraints per axis solved by longest path, derived positions (midway,
     equal spacing) afterwards, errors that name contradicting relations,
     undetermined boxes and overlapping boxes. Properties: every relation
     holds; no coordinate can be smaller; the result does not depend on the
     order relations are written in.
   - Routing around placed boxes — experiment first, stop for the author: a
     simple router through the channels between rows and columns against
     libavoid loaded separately, on the three examples and on book maps with
     their hand positions; report quality, size and licence.
8. **Sketches.** Positions as preferred pins with ELK; the book's hand
   positions as sketches, compared with the hand drawings.

## Out of scope

State panel, traced runs, node shapes and nesting (their own records and
tasks); a graphical editor; any engine written here.
